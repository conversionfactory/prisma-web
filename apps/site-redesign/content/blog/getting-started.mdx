Spinning up a production database used to mean provisioning servers, wiring connection pools, and hand-writing SQL you hoped was safe. With Prisma Postgres and the Prisma ORM you go from an empty project to type-safe queries in a few minutes — and every query you write is checked by the compiler before it ever reaches the database.

## Create your database

Create a new Prisma Postgres instance from the console or the CLI. There is nothing to size and nothing to leave running — the database scales to zero when idle and is ready the moment your first query lands.

```bash
npx prisma init --db
```

This provisions the database and drops a connection string into your `.env`, so the next step already has everything it needs.

## Model your data

Describe your data once in `schema.prisma`. That schema is the single source of truth: it drives your migrations and generates a fully typed client.

```prisma
model Post {
  id        Int      @id @default(autoincrement())
  title     String
  content   String?
  published Boolean  @default(false)
  createdAt DateTime @default(now())
}
```

Run `prisma migrate dev` and Prisma turns the schema into SQL, applies it, and regenerates the client — all in one step.

> Prisma Client is generated from your schema, so every query is fully typed: autocomplete for your models, and a compile error the moment a field name drifts. You catch the mistake in your editor, not in production.

## Write your first query

Because the client is generated, the query below knows `Post` and every one of its fields. Misspell `published` or pass a number where a string belongs and the code won't compile.

```ts
import { PrismaClient } from "@prisma/client"

const prisma = new PrismaClient()

const posts = await prisma.post.findMany({
  where: { published: true },
  orderBy: { createdAt: "desc" },
})
```
